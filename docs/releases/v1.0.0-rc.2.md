# v1.0.0-rc.2 candidate release notes

This document describes the proposed second release candidate. The
`v1.0.0-rc.2` tag has not been created or published.

## Highlights

- Save Manager QR pairing opens an authenticated local manager without typing
  the six-digit code; the manual address-and-code path remains available.
- A tvOS-only Performance HUD option controls Apple's native Metal diagnostics
  live, with no game restart or Apple TV Graphics HUD setting required.
- Nine exact Celeste 1.4.0.0 FNA inputs from itch.io, Epic Games Store, and
  Steam normalize to the same locked game before the shared tvOS build.
- Save Manager reload is more robust when a mutation begins during gameplay.
- Active production code and test projects now use descriptive names instead
  of development-stage names.

## Build options

Build locally on a supported Apple silicon Mac with `./build-tvos.sh`, or use
the separate public template to compile an unsigned IPA in a private GitHub
Actions repository. Cloud compilation is manual-only, pins an immutable public
source commit, and does not sign the app. Follow [Building](../BUILDING.md) or
[Cloud building](../CLOUD_BUILDING.md).

## Supported Celeste inputs

Exactly nine recognized Celeste 1.4.0.0 FNA profiles are supported. They cover
tested Linux, macOS, and Windows packages from itch.io, Epic Games Store, and
Steam. Unknown versions and XNA packages fail closed. See the exact
[input matrix and acquisition guidance](../CELESTE_INPUTS.md).

Users must supply their own lawful Celeste files and FMOD Engine iOS/tvOS
1.10.09 build 97915 SDK. Neither is distributed by this repository.

## Save Manager

Options → Save Manager provides local-LAN downloads, validated replacement and
deletion, Settings reset, one-time QR pairing, and manual six-digit pairing.
Successful mutations return to Celeste through a verified Confirm-driven
high-level reload while the original FNA/SDL/FMOD runtime remains alive. Fully
closing the app from the Apple TV app switcher remains the safe fallback if a
reload fails verification.

## Controller and UI

Automatic, Xbox, PlayStation, Nintendo Switch, and Stadia prompt artwork modes
remain available. Prompt selection changes artwork only; it does not remap any
controller input. Main-menu Quit uses the foreground/background-aware Leave
Celeste screen and no longer destroys the active FNA runtime.

## Performance HUD

Options → Performance HUD toggles Apple's native Metal HUD immediately. It is
Off by default, needs no restart, and keeps Metal logging disabled. Diagnostic
overlays can theoretically add small overhead, although accepted testing found
no measurable practical difference while the HUD was Off.

## Cloud compilation

The public template must first create a private repository. Its privacy gate
runs before checkout or private-input download, inputs and output use fixed
private Release tags, and cleanup removes both proprietary inputs and the
unsigned output. Cloud builds consume the user's GitHub Actions allowance and
still require a separate local signing/install step.

## Fixes since RC1

- Added one-time QR pairing and retained manual authentication.
- Added live Metal Performance HUD control.
- Added exact multi-store/platform input profiles and acquisition guidance.
- Improved local builder phase progress, heartbeat, failure summaries, and
  verbose diagnostics.
- Added the private GitHub Actions compilation path.
- Corrected the active-Level Save Manager soft-reload transition.
- Replaced historical stage-number names in active production code without
  changing persistence, protocol, or runtime behavior.

## Upgrade and persistence compatibility

Same-identity replacement installs retain the existing app-private domain.
Persistence format v2 remains current; v0, v1, and v2 remain readable. The
Controller Prompts and Performance HUD host preferences remain independent of
Celeste Settings and Save Manager imports.

## Known limitations

- Only the nine listed exact Celeste 1.4.0.0 FNA profiles are accepted.
- Everest/mods and XNA inputs are unsupported.
- There is no iCloud/cloud-save sync or uninstall-survival guarantee.
- Personal Team builds do not provide Apple User Management profiles.
- The user must supply the official FMOD iOS/tvOS SDK through their own FMOD
  account.
- Cloud output is unsigned and GitHub never receives signing credentials.
- Cloud output requires a separate signing and installation step.
- Cloud builds consume the user's GitHub Actions allowance.
- App Store distribution and Apple Game Mode support are not claimed.
