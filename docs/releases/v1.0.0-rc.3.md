# v1.0.0-rc.3 candidate release notes

This document describes the accepted third release candidate.

## What changed since RC2

- The main README and supporting guides now begin with the choices and steps a
  first-time builder needs, while retaining detailed references for developers.
- Local and private-cloud build routes are separated more clearly, including
  exact FMOD Engine iOS/tvOS 1.10.09 build 97915 guidance.
- Save Manager normally reopens at the stable local port `49728`, so an open
  phone page can detect that the Apple TV manager closed and later reopened.
- The browser now reports Connected, Checking, Disconnected, Reopened, and
  Session expired states, and disables stale controls safely.
- Every Save Manager activation still creates fresh authentication, QR, CSRF,
  revision, and instance state.
- If another service occupies port `49728`, Save Manager uses one temporary
  local port for that activation and returns to `49728` next time it is free.

## Build options

Build locally on a supported Apple silicon Mac with `./build-tvos.sh`, or use
the separate public template to compile an unsigned IPA in a private GitHub
Actions repository. Cloud compilation is manual-only, pins the immutable RC3
product-source commit, and never signs the app. Follow [Building](../BUILDING.md)
or [Cloud building](../CLOUD_BUILDING.md).

## Supported Celeste inputs

Exactly nine recognized Celeste 1.4.0.0 FNA profiles are supported. Tested
Linux, macOS, and Windows packages from itch.io, Epic Games Store, and Steam
normalize to one locked canonical game. Unknown versions and XNA packages fail
closed. See the [input matrix](../CELESTE_INPUTS.md).

Users must supply their own lawful Celeste files and the official FMOD Engine
iOS/tvOS 1.10.09 build 97915 SDK. This repository distributes neither.

## Save Manager

Options → Save Manager provides local-LAN backup downloads, validated
replacement and deletion, Settings reset, one-time QR pairing, and manual
six-digit pairing. The browser can detect closure, reopening, and session
expiry at the stable normal address, but a reopened manager always requires
fresh authentication. Successful mutations use the verified Confirm-driven
high-level reload while the original FNA/SDL/FMOD runtime remains alive.

## Controller, Quit, and diagnostics

Automatic, Xbox, PlayStation, Nintendo Switch, and Stadia prompt artwork modes
remain available. Main-menu Quit uses the safe Leave Celeste flow rather than
destroying the FNA runtime. Options → Performance HUD controls Apple's native
Metal diagnostics live, defaults Off, and keeps HUD logging disabled.

## Upgrade and persistence compatibility

Same-identity replacement installs retain the app-private domain. Persistence
format v2 remains current, with v0, v1, and v2 readable. Controller Prompts and
Performance HUD host preferences remain independent of Celeste Settings and
Save Manager imports. RC3 introduces no persistence migration.

## Known limitations

- Only the nine exact listed Celeste 1.4.0.0 FNA profiles are accepted.
- Everest/mods and XNA inputs are unsupported.
- There is no iCloud or other cloud-save synchronization, and uninstalling may
  remove local saves.
- Personal Team builds do not provide Apple User Management profiles.
- The user must supply the exact official FMOD SDK through their own account.
- Cloud output is unsigned, consumes the user's Actions allowance, and needs a
  separate signing/install step; GitHub receives no signing credentials.
- App Store distribution and Apple Game Mode support are not claimed.
